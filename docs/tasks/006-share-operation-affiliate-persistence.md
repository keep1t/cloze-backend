## Implementation contract

### Private persistence

- `private.share_operations` has `owner_id uuid not null references auth.users(id) on delete cascade`, `operation_id uuid not null`, `share_id uuid not null unique references private.share_snapshots(share_id) on delete cascade`, trimmed nonempty `token_key_version text`, and `created_at timestamptz not null`, with primary key `(owner_id, operation_id)`. Persisting the non-secret key version makes exact replay durable without storing token material.
- `private.share_snapshot_affiliate_links` has `share_id uuid not null references private.share_snapshots(share_id) on delete cascade`, `position integer not null check (position > 0)`, trimmed nonempty `garment_ref text`, and trimmed nonempty `url text`, with primary key `(share_id, position)` and unique `(share_id, garment_ref)`.
- `private.share_snapshot_cleanup` has `share_id uuid primary key references private.share_snapshots(share_id) on delete cascade`, nullable `object_deleted_at timestamptz`, nullable `claimed_at timestamptz`, nullable `claim_token uuid`, `attempt_count integer not null default 0 check (attempt_count >= 0)`, and nullable nonblank `last_error_code text`. A claim timestamp and token must be both null or both non-null; a deleted object cannot retain a claim.
- All tables are private, RLS enabled and forced, have no policies, revoke all table privileges from `PUBLIC`, `anon`, `authenticated`, and `service_role`, then grant CRUD only to `service_role`.

### Atomic service function

```sql
private.create_share_operation(
  p_owner_id uuid,
  p_operation_id uuid,
  p_share_id uuid,
  p_token_hash bytea,
  p_token_key_version text,
  p_upload_expires_at timestamptz,
  p_expires_at timestamptz,
  p_affiliate_links jsonb,
  p_now timestamptz
) returns table (decision text, share_id uuid)
```

- The function is `SECURITY INVOKER` with `search_path = ''`; revoke public/client execution and grant execute only to `service_role`.
- It accepts a nonempty token hash, trimmed nonempty key version, `p_upload_expires_at > p_now`, `p_expires_at >= p_upload_expires_at`, and a JSON array of zero or more exact `{ "garment_ref": string, "url": string }` objects. Fields must be trimmed, nonempty strings; extra/missing fields and duplicate garment references are invalid.
- Array ordinal defines the persisted positive `position`; callers do not pass positions. An empty affiliate array is valid.
- A transaction-scoped advisory lock serializes the same owner and operation. First creation atomically creates the T04 pending snapshot, operation row, ordered affiliate rows, and a default cleanup row.
- Matching immutable input returns `replay` and the existing `share_id` without mutation or new rows. Any immutable mismatch returns `conflict` and a null `share_id` without mutation. An unrelated share-ID or token-hash uniqueness collision also returns non-disclosing `conflict` with null ID and creates no rows.
- Structural input failures raise `P0001` and roll back all resources. The SQL function trusts `p_owner_id` only as server-derived Edge input; it never uses JWT metadata or client-provided owner authority.

### Correction history

- Round 1 of 3 (developer): migration and test delivered; the restricted author's
  test suite exposed a test-file defect — `has_function_privilege('PUBLIC', ...)`
  raises SQLSTATE 42704 (`role "PUBLIC" does not exist`) in PostgreSQL 17.6. That
  was a hard SQL error that aborted the pgTAP script and is not a migration problem;
  the test author replaced that assertion with an `aclexplode`-based check on
  `pg_proc.proacl` and added trimmed-input contract cases per TF-01.
- Round 2 of 3 (developer): after the coordinator applied the migration, `make
  test-db` and `make db-lint` surfaced SQLSTATE 42702 (`column reference "share_id"
  is ambiguous`) at the `IF` around migration line 206: the uniqueness precheck used
  `where share_id = p_share_id` while the function's output variable `share_id`
  collided with the `private.share_snapshots` column. All affected table-column
  references in that function were qualified with a `ss` alias. The pgTAP run then
  exposed one remaining grant defect: the three new tables' owner (the migration
  role) retained default full-owner ACL entries
  (`postgres=arwdDxtm/postgres`), so the effective ACLs were not service-exclusive.
  The migration now revokes those owner entries with
  `revoke all on table ... from current_user` before granting CRUD only to
  `service_role`, aligning with AC4 and the test's "only explicit CRUD grants"
  assertion.
- Round 3 of 3 (developer): independent reviewer R1 identified that nullable
  required inputs and non-string affiliate fields bypassed structural validation.
  In PL/pgSQL, NULL parameters passed through existing guards because `octet_length(null)`
  → null, `length(trim(null))` → null, `null <= value` → null (not true), and
  `jsonb_typeof(null)` → null all evaluate to falsy comparisons rather than raising.
  Additionally, `v_link->>'garment_ref'` coerces any JSON value to text via the
  `->>` operator, so integers (→ `'1'`) and booleans (→ `'true'`) passed the
  existing trim/length checks. The migration now: (a) rejects NULL for every required
  parameter upfront with `is null` checks before any other validation; and (b) adds
  explicit `jsonb_typeof(v_link->'garment_ref') <> 'string'` and
  `jsonb_typeof(v_link->'url') <> 'string'` guards using the `->` operator
  (returns the raw JSON value) rather than `->>` (text coercion). The test author
  added 10 corresponding pgTAP cases for integer/boolean `garment_ref`, integer/
  boolean `url`, and NULL `p_affiliate_links`; the corrected migration passes all
  329 tests. No side effects are introduced before structural validation.
- R1 resolution (task 012, separate round budget 0/3): the historical
  three-correction-round limit was not reset; the coordinator authorized a new
  task instead of a fourth correction round. See
  [`docs/tasks/012-t06-r1-null-safe-affiliate-fields.md`](012-t06-r1-null-safe-affiliate-fields.md).
